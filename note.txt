top-down recursive descent



our current expression path is a hand-rolled cascade — parseExpression (+/-) calls parseTerm (*//) calls parseFactor — with comparisons bolted on separately in
 parseComparisonExpression (only reachable inside if) and the whole thing duplicated again as parsePrintExpression/parsePrintTerm. Five functions, 
 and comparisons work in some contexts but not others.

Now add %, unary -, unary !, &&, ||, and function calls. That cascade becomes eight nested levels, twice over.

Precedence climbing collapses it to one function and a table. It's still recursive descent — just a better encoding of precedence:



    int precedenceOf(TokenType t)
    {
        switch (t)
        {
            case TokenType::Or:                                                          return 1;
            case TokenType::And:                                                         return 2;
            case TokenType::Equal:  case TokenType::NotEqual:                            return 3;
            case TokenType::Less:   case TokenType::LessEqual:
            case TokenType::Greater:case TokenType::GreaterEqual:                        return 4;
            case TokenType::Plus:   case TokenType::Minus:                               return 5;
            case TokenType::Multiply: case TokenType::Divide: case TokenType::Percent:   return 6;
            default:                                                                     return 0;  // not binary
        }
    }

    ExprPtr Parser::parseExpr(int minPrec)
    {
        ExprPtr left = parseUnary();

        for (;;)
        {
            const int prec = precedenceOf(m_tok.type);
            if (prec == 0 || prec < minPrec)
                break;

            const Token op = m_tok;
            advance();
            ExprPtr right = parseExpr(prec + 1);      // prec + 1 == left-associative
            left = makeBinary(std::move(left), op, std::move(right));
        }
        return left;
    }


parseUnary handles prefix - and ! then defers to parsePrimary (literal, identifier, ( expr ), call). Adding an operator later is one row in the switch. Right-associativity, if you ever need it, is parseExpr(prec) instead of prec + 1.

Two things to decide while rewriting
Make assignment a statement, not an expression. Right now it's discovered mid-parseTerm, which is why you needed the 
"chained assignments are not allowed" check and a separate "assignment not allowed in print" error. 
If parseStatement sees an identifier followed by =, it's an assignment; otherwise it's an expression statement. 
Both special cases disappear, and expressions get simpler because they never produce assignments.

Report and recover instead of throwing. This is the parser half of the diagnostics work. On an unexpected token: 
report it, then skip tokens until a Newline, }, or Eof, then resume. Your language is newline-terminated, 
so synchronization is unusually clean — better than C's. That's what turns "one error per run" into "all your syntax errors at once."
